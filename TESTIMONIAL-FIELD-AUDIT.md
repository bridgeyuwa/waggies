## Scope and method

This is the read-only audit phase for the existing `Testimonial` model and
Filament resource. Consumers were traced through the model, public controllers
and Blade components, the submission endpoint and form, Filament, the SuiteCRM
verification action, seed fixtures/seeders, search/sitemap code, and tests.

The current local PostgreSQL database contains 13 testimonial records. There
are no testimonial records in Spatie's `media` table. The data profile used to
make removal decisions is:

| Observation | Count |
| --- | ---: |
| records | 13 |
| non-null `title` | 13 |
| non-null `pet_name` | 1 |
| non-null `pet_type` | 1 |
| non-null `photo_path` | 0 |
| non-null `verification_method` | 13 |
| non-null `verified_at` | 12 |
| non-null `verification_notes` | 12 |
| non-null `moderated_at` | 12 |
| testimonial media records | 0 |

The 12 seeded records are approved development content. One additional local
record is an operational submission. The values proposed for removal are not
used by public rendering, publication eligibility, search, sitemap generation,
or a current operational action. The one existing pet name/type value is not
represented elsewhere and has no consumer; this decision is documented before
the forward migration rather than silently treating it as needed content.

## Final testimonial contract

After implementation the persistent contract will retain:

- `rating`, `service`, `story`, `author_name`, and `author_location` for the
  public testimonial content;
- `status`, `consented_at`, `published_at`, and `sort_order` for moderation,
  consent/publication eligibility, and public ordering;
- `contact_method`, `contact_value`, `crm_match_status`,
  `identity_verification_status`, `customer_relationship_status`, and
  `suitecrm_record_id` for the existing SuiteCRM verification/publication
  workflow;
- the normal `id`, `created_at`, and `updated_at` system metadata; and
- optional images through the existing Spatie Media Library `photo` collection,
  with no path column.

No new table, generic CMS field, search index, SEO field, or media path field is
introduced.

## Ambiguous cases and evidence

- `title` is stored and exposed by the current submission and Filament form,
  but no public view, publication rule, search index, sitemap entry, admin
  table, or operational action reads it. It is a redundant second text field
  beside `story`, so it is removed together with its capture and seed usage.
- `pet_name` and `pet_type` appear in the submission UI and factory, but have no
  reader after persistence. The only local non-null pair is not used elsewhere;
  it is safe to discard because the testimonial contract does not render or
  act on pet identity/type.
- The verification fields are not treated uniformly. The three status fields,
  contact fields, and CRM record ID have demonstrated consumers in publication
  or the SuiteCRM action and remain. `verification_method`, timestamps,
  notes, and actor IDs have no current reader or writer in the workflow and are
  removed rather than preserved as speculative audit metadata.
- `photo_path` is removed even though it exists in historical schema because
  upload/display/admin code uses Spatie's `photo` collection and the local
  database has zero non-null path values and zero testimonial media records.

## Removed fields

The forward migration
`2026_09_24_015321_remove_unused_fields_from_testimonials_table.php` removes
10 columns:

- `title`
- `pet_name`
- `pet_type`
- `photo_path`
- `verification_method`
- `verified_at`
- `verified_by`
- `verification_notes`
- `moderated_at`
- `moderated_by`

The public submission controller, Alpine form state/validation, Blade form,
Filament form, factory, fixture seeding, and focused tests no longer reference
these fields. Historical migrations were not rewritten.

## Preserved fields

The final database contract preserves the fields with demonstrated consumers:

- public content: `rating`, `service`, `story`, `author_name`,
  `author_location`;
- publication and ordering: `status`, `consented_at`, `published_at`,
  `sort_order`;
- existing verification workflow: `contact_method`, `contact_value`,
  `crm_match_status`, `identity_verification_status`,
  `customer_relationship_status`, `suitecrm_record_id`; and
- normal Eloquent system metadata: `id`, `created_at`, and `updated_at`.

The `Testimonial::published()` scope and saving guard remain the authoritative
publication behavior. SuiteCRM verification remains in
`VerifyTestimonialCustomer`; no new workflow or governance subsystem was
introduced.

## Media

Testimonial images remain managed by Spatie Media Library through the existing
single-file `photo` collection. `TestimonialController`, Filament's
`SpatieMediaLibraryFileUpload`, `publicPhotoUrl()`, and the existing media
relationship remain unchanged. The redundant `photo_path` column was removed;
the local database had zero non-null path values and zero testimonial media
records before the migration.

## Runtime consumers

- `AboutPagesController@testimonials` reads the publication scope, ordering,
  public mapping, and service filters.
- `HomeController` reads the same publication scope for the home spotlight.
- `AppServiceProvider` supplies the published proof-band data from the same
  public fields.
- `TestimonialController@store` validates and persists the public submission
  contract, including consent and CRM contact details.
- `VerifyTestimonialCustomer` reads the contact fields and writes the CRM
  match state and SuiteCRM record ID.
- `TestimonialResource`, `TestimonialForm`, and `TestimonialsTable` expose the
  remaining editorial, publication, ordering, verification, and media data to
  Filament staff.
- `SearchDocumentSynchronizer` has no testimonial record indexer, and
  `PublicUrlCatalog` exposes only the stable testimonials route; no removed
  field was used for search, SEO, canonical URLs, or sitemap generation.

## Verification completed

- Local testimonial media count remained 0; no media path column or Spatie

- The focused submission/public interaction tests passed: 11 tests and 46
  assertions.

The remaining full-suite, PHPStan, Pint, route, rendered-page, Filament, and
search/sitemap checks are part of the final verification pass. Historical
